# The engine's operations

Generated by `bun scripts/operations.ts` from the engine's tools as `src/iface/` registers them and their files in `guidance/.tools/`. Do not edit it by hand: change a tool or its file and run the script again (`--check` says whether this file is current).

14 everyday operations, 3 more fixed tools, 82 searchable tools and 10 map tools.

## Everyday operations

Each is one item of `world_apply`'s `operations` list, named by `op`. A call's operations are applied in order and recorded in one write; a later one may name what an earlier one made.

An operation whose entry says it takes its provenance takes these three arguments:

| Argument | Shape | What it is |
|---|---|---|
| `source` | one of prose, lore, author, gm, character, player, default, invented, or object: from, lore, message, roll, gap_check, consent | Where it comes from (horizon takes none). lore, message and roll cite an entry, message or roll by id; an invention cites its gap_check and consent. |
| `precision` | one of exact, approximate, vague, unknown |  |
| `standing` | one of established, proposed, assumed |  |

### move

go somewhere, others along

Lane: engine. Needs: `who`, `to`. Takes its provenance.

| Argument | Shape | What it is |
|---|---|---|
| `who` | text | move: who or what goes. wear: who wears it. pay: who pays. relate: whose regard changes. act: who takes the action; left out, the player's character. |
| `to` | text | move: the place. give: who receives it. pay: who is paid (none: no one in the world). relate: whom they regard. |
| `with` | list of text | move: others who go along. |
| `square` | list of whole number | move, place: the square on the map, [column, row] from 1 at the top left as the map prints it. |
| `near` | text | move, place: who or what to stand beside on the map. |
| `zone` | text | move, place: a zone of the place's map. |
| `why` | text | move, place, give, store, quest, relate: the reason, kept with the change. |

Reports its code (`src/iface/ops-things.ts`) can give: `kept_nowhere`, `not_holding`, `not_to_hand`, `not_wearable`.

Worked example:

```json
{
  "operations": [
    {
      "op": "move",
      "who": "bram",
      "to": "market_square",
      "with": [
        "odile"
      ],
      "source": {
        "from": "prose",
        "message": "m-0012"
      },
      "standing": "established"
    }
  ]
}
```

## Fixed tools

The agents' own list holds these with `world_apply`: read the tree at a point and depth, find by words, and roll.

#### world_query

Reads the world's tree at a point: the point with its values and where each comes from, the levels beneath it to the depth asked, each with a line on what is beneath it. At a place opened in full it also gives the place's record, a line for each entry: its base and the lore entries it comes from, its ways to other places with the minutes and distance by each way of travel, what adjoins it, and the newest few entries of each of what the story changed there (since), its features and its access, with a line saying how many more there are and the query that reads them; a part with nothing in it says so. At a quest it gives its record whole: what it is, each stage with its condition as written, its state and the reason it was last moved, who and where it involves, its stakes and rewards, what the player may see of it, where it comes from, its thread and that thread's state, and the beats that moved it, the newest first, with how many more there are; and for a stage the world built, what the world authored for it: its effects, rewards, gate, truth, cue, hints and the stages it goes on to. Asked for a span, it also lists what falls due in that span there; it applies none of it.

Reads; changes nothing.

| Argument | Shape | Needed | What it is |
|---|---|---|---|
| `at` | text | yes | The point of the tree: a place, someone or something (by name or id), world, groups or elsewhere; or ruleset for the world's ruleset and its bestiary; or quests for one line of data on each quest, or a quest by its name, its id or quest:<id> for its record whole. |
| `depth` | whole number, or one of full |  | How many levels below the point to show, or full for everything beneath it. |
| `due` | text |  | A span ahead (two hours, until 22:00, until a part of the world's day by its name, or a date and time YYYY-MM-DD HH:MM): what falls due in it at that part of the tree. |
| `map` | true or false |  | true to add the place's map as text. |

A place that has a map already is laid over in this chat only, and the answer says so; the world's own map is untouched, and a swipe takes it back. A map is at most 64 by 64 squares: lay a larger place in parts, each its own place over its square of a coarser map. With over and square it lies over one square of a coarser map, for the place drawn there or a new one. The map belongs to the chat, and keeps how wide a square is and how time passes on it: a map of 5 ft squares counts rounds of seconds. Whoever stood on that coarse square stands on no square of the new map until placed on it. With remove it takes the map of the place out of this chat's world instead (a map laid in error), and the squares and doors drawn on it stay recorded, shown again if a map is laid there. To keep a laid map in the world, world_keep.

Writes the engine lane.

| Argument | Shape | Needed | What it is |
|---|---|---|---|
| `place` | text | yes | The place to lay a map for. With over and square, the name of a new place made on that square when none is drawn there; a place the square does not hold is not laid for, the one it holds is. |
| `rows` | list of text |  | The map's rows, top first, one symbol to a square: # wall, . floor, + door, a space nothing, and the legend's own symbols; a symbol no legend names reads as floor and is reported. At most 64 rows of 64 squares. |
| `width` | whole number |  | Without rows: a walled room this many squares wide, floor inside. |
| `height` | whole number |  | Without rows: how many squares high the room is. |
| `doors` | list of list of whole number |  | Without rows: the squares of the room's walls that are doors, each [column, row]; one outside the room is reported and not drawn. |
| `legend` | object |  | What the rows' other symbols stand for: wall, floor, door, or words, read as floor named by them ({"~": "shallow water"}); with "blocks": true a square nobody walks through ({"T": {"terrain": "table", "blocks": true}}); or {"c": {"item": "chest"}}, {"z": {"zone": "dais"}}. |
| `feet` | number |  | How wide a square is, in feet; the usual 5 ft when left out. |
| `title` | text |  | The map's title. |
| `over` | text |  | The place whose coarser map this one lies over one square of: a building on a town's map. Where that map draws the place, its square opens onto this map. |
| `square` | list of whole number |  | With over: that square of the coarser map, [column, row]. |
| `remove` | true or false |  | true to take the map of place out of this chat's world again, as when one was laid in error; whoever stood on its squares stands on none. Only the map laid in play is meant: the world's own map is changed square by square (map_edit). |

Worked example:

```json
{
  "place": "The Far Road",
  "width": 12,
  "height": 8,
  "source": {
    "from": "prose",
    "message": "m-0042"
  },
  "standing": "assumed"
}
```

#### map_edit

Changes part of a place's map of squares without redrawing it: squares, rectangles and lines drawn with a symbol, and its legend added to or changed, for a wall, a door, a fixture, terrain or a zone; a place whose grid was written without a map (a starter world's) is changed the same way. The change is kept square by square over the map, so a later change to the world's own map still shows through. What a stroke reaches off the map is left out, and the answer says once for each such stroke how many of its squares that was. A symbol no legend names is read as floor, reported so you name it, and what was drawn with it is recorded as assumed. A fixture drawn on the map can become a thing of its own in the same call, with things.

Writes the engine lane.

| Argument | Shape | Needed | What it is |
|---|---|---|---|
| `at` | text | yes | The place whose map to change. |
| `strokes` | list of object: symbol, squares, rect, line |  | What to draw, in order: a symbol on squares, in a rectangle or along a line. |
| `legend` | object |  | Symbols to add or change, as map_lay's legend: words are floor named by them, with "blocks": true a square nobody walks through ({"b": {"terrain": "bar", "blocks": true, "seeThrough": true}}); null takes one out. |
| `things` | list of object: square, name |  | Fixtures drawn on the map to make things of, each by one of its squares: the squares drawn with that same symbol of terrain become floor, and a thing of the terrain's name (or the name given) stands where it was drawn, as large as those squares and blocking what the terrain blocks. |

Worked example:

```json
{
  "at": "The Cellar",
  "strokes": [
    {
      "symbol": "#",
      "squares": [
        [
          5,
          3
        ]
      ]
    },
    {
      "symbol": "t",
      "rect": [
        [
          6,
          2
        ],
        [
          7,
          2
        ]
      ]
    }
  ],
  "legend": {
    "t": {
      "terrain": "table",
      "blocked": true
    }
  },
  "things": [
    {
      "square": [
        8,
        4
      ],
      "name": "overturned table"
    }
  ],
  "source": {
    "from": "gm"
  }
}
```

#### world_map_place

Puts a place on a map, moves it, renames it, says which map draws its inside (its opens), or takes it off. A place put on a map is a new place of the world, inside the map's scope, and its id must be one no place has yet. To put one, give map and name; to change one, name it in place and give what changes. A place's description and other fields are not the map's: they cannot be set here. Taking a place off the map takes it out of this chat's world, with the map's links to it. It writes this chat's own world, played at once and kept by world_keep; a map the world draws is changed square by square (map_edit). A call that leaves the map as it stands says so.

Writes the engine lane.

| Argument | Shape | Needed | What it is |
|---|---|---|---|
| `map` | text | yes | The map: its id or its title, as this chat plays it. |
| `place` | text |  | The place on the map to change or take off: its id or its name. Leave it out to put a new place on the map. |
| `name` | text |  | The place's name: Bluebird Coffee. For a place already on the map, its new name. |
| `id` | text |  | The id for a new place: letters, digits and _. Leave it out and it is made from the name. |
| `x` | whole number |  | Where it is on the map, from the left, a whole number from 0: a position in the map's frame on a node map, a square's column (from 0) on a grid map. It goes with y. |
| `y` | whole number |  | Where it is on the map, from the top, a whole number from 0. It goes with x. |
| `opens` | text |  | The map that draws the inside of this place: its id or title. That map's scope must be this place, so lay it first (map_lay). |
| `remove` | true or false |  | true to take the place off the map, and its links with it. |

Worked example:

```json
{
  "map": "Thornbury",
  "name": "Bluebird Coffee",
  "x": 4,
  "y": 3,
  "source": {
    "from": "prose",
    "message": "m-0042"
  }
}
```

#### world_map_link

Links two places on a map so people can travel between them, changes a link, or removes one. A map's links become the world's paths. Once a map has any link, its places join only where they are linked: link every place of the map, or none. Two places may have one link for each way of travelling. A link may also lead to a place that is not on the map, by its id. It writes this chat's own world, played at once and kept by world_keep. A call that leaves the map as it stands says so.

Writes the engine lane.

| Argument | Shape | Needed | What it is |
|---|---|---|---|
| `map` | text | yes | The map: its id or its title, as this chat plays it. |
| `from` | text | yes | One end of the link: a place, by its name or id. |
| `to` | text | yes | The other end: a place, by its name or id. |
| `mode` | one of walk, road, offroad, water |  | The way of travelling: walk, road (driving), offroad or water (by boat). Walk when left out for a new link; needed to pick one when the two places have several links. |
| `minutes` | number |  | How long the link takes, in minutes. Needed for a new link. |
| `one_way` | true or false |  | true: the link only leads from from to to. false: both ways. Left out, a new link goes both ways and an existing one stays as it is. |
| `remove` | true or false |  | true to remove the link instead: the one of that mode when mode is given, else every link between the two. |

Worked example:

```json
{
  "map": "Thornbury",
  "from": "Market Square",
  "to": "The Lamp and Ladle",
  "minutes": 3,
  "source": {
    "from": "prose",
    "message": "m-0042"
  }
}
```

#### world_map_settings

Changes how the world's maps work: what the player's map shows, whether people walk grid maps square by square, how far the player character sees on one, and whether travel needs a path. Give only what changes; the answer gives the settings as they stand after it. It writes this chat's own world, played at once and kept by world_keep.

Writes the engine lane.

| Argument | Shape | Needed | What it is |
|---|---|---|---|
| `display` | one of knowledge, fog |  | What the player's map shows: knowledge (the places the player character knows, those only heard of drawn dashed) or fog (fog over what it has not seen). |
| `grid_movement` | true or false |  | true: the grid system is on, so walls and doors steer people across grid maps, things lie on squares, and squares and zones can trigger rules. false: grid maps are drawn, not walked. |
| `sight_radius` | whole number |  | With the grid system on, how many squares around it the player character sees: a whole number. |
| `travel_simulation` | true or false |  | true: going somewhere needs a path that leads there. false: a move the story tells simply lands. |

Worked example:

```json
{
  "display": "fog",
  "sight_radius": 6,
  "source": {
    "from": "prose",
    "message": "m-0042"
  }
}
```

#### world_keep

Copies what this chat changed of its world's maps into the world's draft, the working copy the world's owner edits in Build: maps laid in play with the squares drawn on them, the places, paths and map settings this chat changed. Only what you name is kept, each written whole over what the draft holds, and a change made to the draft meanwhile stands beside it. The chat keeps its own changes: they leave it when the world takes them in. With nothing named, the answer lists what this chat has changed. Keeping puts nothing in the world's published revisions; the owner commits the draft.

Writes the engine lane. Takes no provenance.

| Argument | Shape | Needed | What it is |
|---|---|---|---|
| `maps` | list of text |  | The maps to keep, each by id or title: a map laid in play, or one the world draws that this chat drew squares on (the squares are laid on it). |
| `places` | list of text |  | The places of the world's own that this chat changed, each by id or name. |
| `paths` | list of text |  | The paths (links between places) of the world's own that this chat changed, each by id. |
| `settings` | true or false |  | true to keep the map settings this chat changed. |

Worked example:

```json
{
  "maps": [
    "The Far Road"
  ],
  "settings": true
}
```
